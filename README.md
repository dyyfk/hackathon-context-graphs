# Hackathon: Context Graphs for Multi-Agent AI

Side-by-side demo showing how a Neo4j context graph + Cypher-generating agent beats vanilla vector RAG on structured questions over Stack Overflow Q&A.

Built for the [Hack Day at AWS Builder Loft SF, May 19 2026](https://luma.com/bchosur4) using patterns from the [AWS "stop AI agent hallucinations" workshop](https://github.com/aws-samples/sample-stop-ai-agent-hallucinations-workshop).

## What it shows

Two agents answer the same questions over the same Stack Overflow corpus:

- **Vanilla RAG** — FAISS vector search over 1,000 question/answer passages, top-3 retrieval.
- **Graph-RAG** — Cypher generated by the LLM, executed against a Neo4j knowledge graph (1,589 questions, 1,367 answers, 1,365 users, 476 tags).

Both wrap Claude Sonnet 4.5 via [Strands Agents](https://strandsagents.com).

| # | Question type | Vanilla RAG | Graph-RAG |
|---|---|---|---|
| 1 | Count of cypher questions with accepted answers | "I cannot. Write SQL." | **467** |
| 2 | Users who answered 'cypher' AND asked 'java' | "I cannot. Write SQL." | 9 users, listed by name |
| 3 | Top 5 tags co-occurring with 'neo4j-apoc' | "I cannot. Write SQL." | neo4j 122, cypher 86, graph-databases 9, graph-data-science 4, csv 4 |
| 4 | Cypher questions with >50,000 views (**Antarctica test**) | "I cannot get view counts" | **0** — and proves it with the real ceiling (1,851 views, named question) |

In every case, vanilla RAG capitulates and tells you to write SQL against Stack Exchange. Graph-RAG just runs the query and gives the number. In the empty case (Q4), Graph-RAG doesn't just say "no results" — it returns the actual max to prove the empty answer is correct.

## Architecture

```
                   ┌─────────────────────┐
                   │ Claude Sonnet 4.5   │  ← Anthropic API
                   │ (via Strands)       │
                   └──────────┬──────────┘
                              │
                ┌─────────────┴──────────────┐
                ▼                            ▼
   ┌──────────────────────┐      ┌───────────────────────┐
   │  search_questions    │      │ query_knowledge_graph │
   │  (FAISS + MiniLM)    │      │  (Cypher)             │
   └──────────────────────┘      └───────────────────────┘
                │                            │
                ▼                            ▼
       passages (top-3)             Neo4j Sandbox
                                    (Stack Overflow graph)
```

## Setup

Prereqs:
- Python 3.10+
- A Neo4j Sandbox at https://sandbox.neo4j.com — pick the **Stack Overflow** project
- An Anthropic API key (https://console.anthropic.com)

```bash
git clone https://github.com/dyyfk/hackathon-context-graphs
cd hackathon-context-graphs

cp .env.example .env
# Fill in:
#   NEO4J_URI, NEO4J_USER, NEO4J_PASSWORD  (from sandbox "Connection details")
#   ANTHROPIC_API_KEY                       (sk-ant-api03-...)

python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python discover.py     # validate connection + dump real schema
python compare.py      # run the 4-query side-by-side demo
```

First run of `compare.py` builds the FAISS index over 1,000 questions (~30s) and caches it to `_rag_index.faiss`.

## Files

| File | Purpose |
|---|---|
| `graph.py` | Neo4j connection + `run_cypher` helper |
| `model.py` | Strands Anthropic provider config |
| `discover.py` | Schema introspection — run first to verify setup |
| `graph_agent.py` | Graph-RAG agent (Strands + Cypher tool) |
| `rag_agent.py` | Vanilla RAG agent (Strands + FAISS tool) |
| `compare.py` | Runs both agents through the 4 hero queries |

## Switching domains

The Stack Overflow sandbox is one of ~15 pre-built Neo4j Sandbox graphs (Crime Investigation, Paradise Papers, Movies, Twitter, etc.). To target a different one:

1. Provision the sandbox at sandbox.neo4j.com
2. Update `.env` with its connection details
3. Run `python discover.py` and copy the actual schema into the system prompt in `graph_agent.py`
4. Rewrite the 4 queries in `compare.py` against the new schema
